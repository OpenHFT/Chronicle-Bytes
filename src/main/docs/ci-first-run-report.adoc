== Requirements, Tests and Coverage (Snapshot)

* Requirements catalogue:
** Chronicle Bytes defines 57 requirements with `CB-*` identifiers in `src/main/docs/project-requirements.adoc` (functional, non-functional, documentation, test and risk).
* Test suite:
** There are 160+ test classes under `src/test/java/net/openhft/chronicle/bytes`, covering core `Bytes`/`BytesStore` behaviour, encoding/decoding, mapped files, pooling and various edge cases.
** Tests predate the explicit requirement IDs and therefore do not yet systematically reference `CB-*` identifiers in comments.
* Coverage configuration:
** Chronicle Bytes sets module-specific JaCoCo thresholds in `Chronicle-Bytes/pom.xml`:
*** `jacoco.line.coverage = 0.710`
*** `jacoco.branch.coverage = 0.623`
** The root parent POM (`OpenHFT/root-parent-pom/pom.xml`) configures `jacoco-maven-plugin` to:
*** generate HTML coverage reports at `target/site/jacoco/index.html`; and
*** enforce the configured coverage thresholds during the `verify` phase.
** CODE_REVIEW_STATUS.md notes that for Chronicle Bytes the `code-review` profile has had thresholds tightened to higher values (line ≈ 0.8859, branch ≈ 0.7543) with `mvn clean verify -Pcode-review` passing from the module root.
* Actual coverage metrics (this run):
** Running `mvn -pl Chronicle-Bytes -am verify` locally completed successfully and produced a `Chronicle-Bytes/target` directory, including a `site/jacoco` report tree.
** Exact coverage percentages have not yet been extracted into a summary file for this first run.
